---

带用户**从零**完成第一次。他可能完全没用过 agent 工具，也不知道自己的数据能怎么弄出来。
你的任务是**一步一停**：每步只让他做一件事，做完确认了再往下，不要一次性倒一大堆步骤给他。

贯穿始终的三条：
- **数据只留本地**，`workspace/` 已被 gitignore，永远不外发。
- **绝不代他输入账号、密码、短信验证码。**
- 你不做医学诊断，只是把他已有的报告重新组织展示。

---

## 第 0 步 · 先让他看见成品（30 秒，建立信心）

别一上来就问数据。先跑演示，让他知道最后能得到什么：

```bash
python3 demo/make_demo.py && python3 -m webbrowser -t demo/index.html
```

打开后告诉他：**这是合成的假数据**，但功能就是他将来会得到的那些——
化验能看多年趋势、报告能翻原件、影像图能放大、两次体检能对比。
问一句：「你想要的是这个吗？」

（浏览器没自动弹出来的话，让他直接双击 `demo/index.html` 就行。）

---

## 第 1 步 · 问清他的数据在哪（这一步最关键）

**不要猜，直接问。** 把这四个选项念给他：

> 你的体检 / 检查报告现在在哪？（可以多选，混着来很正常）
> 1. **手里已经有 PDF 或照片了** —— 最省事
> 2. **在医院 / 体检机构的网站上，我能用电脑登录**
> 3. **在微信或支付宝的医院小程序、公众号里**
> 4. **不知道 / 还没找过** —— 我帮你想办法

按他的回答走对应文档，**一次只走一条**：

| 他选 | 你读 | 一句话策略 |
|---|---|---|
| 1 | `docs/12-acquire-manual.md` | 让他把文件拖进 `workspace/inbox/` 就行 |
| 2 | `docs/10-acquire-browser.md` | 先带他装浏览器扩展，再给他那段现成的提取提示词 |
| 3 | `docs/11-acquire-mobile.md` | **首选电脑版微信打开小程序**，拿到链接转 Chrome，然后并入路线① |
| 4 | 见下面「第 1.5 步」 | 从他手里已有的一张纸/一份 PDF 倒推 |

### 第 1.5 步 · 他说"不知道"时怎么办

多数人其实有入口，只是没意识到。按这个顺序问：

1. **手边有没有一张打印的化验单或报告？** 有的话拍照给你——
   报告页脚常印着「溯源链接」或二维码，能直接反推出他们医院用哪套系统。
2. **在哪家医院/体检中心做的？** 让他在微信里搜医院名，看有没有小程序或公众号，
   底部菜单常有「报告查询 / 检验结果 / 就医服务」。
3. **有没有当地的健康 App？**（各省的健康码/医保 App 多数带报告查询）
4. 都没有 → 医院自助机能打印，或去窗口拷贝，拿到纸质件后走路线①（拍照）。

## 第 2 步 · 让数据落地（按路线执行，中途多确认）

不管走哪条，目标一致：**文件进 `workspace/inbox/`**。

执行时注意：
- **分批**。报告多的时候别想一次抓完，按年份或按体检批次分批做完再下一批。
- **报数**。每批做完告诉他「预期几份、实际拿到几份」，少了要说清少了哪些，
  不要默默漏掉。
- 用户提供的 Excel/汇总表**不要全信**，它只是加速；原始 PDF 才是准的，后面会交叉校验。

收完立刻勘探，并把结果用人话讲给他听：

```bash
python3 tools/probe.py workspace/inbox
```

告诉他：一共几份、哪些是有文字层的 PDF（能精确取）、哪些是扫描件/照片（要你读图）、
有没有明显缺失的年份。

---

## 第 3 步 · 抽取（你干活，他等着）

按 `docs/20-extract.md`：

- 有文字层 → `python3 tools/extract.py text <file>`，零误差
- 没文字层 → `python3 tools/extract.py pages <file>` 渲染成图，**你自己 `Read` 读**
- 量大 → 可选 `tools/fanout.py` 分批

**对照那 9 个数据坑逐条排查**，尤其这两个最常见：
- 参考区间会随时间变（必须逐次测量存）
- 一次超声多项共用一份报告（要合并，别重复计数）

读不清的数字**不要编**，标「待核对」并告诉他。

---

## 第 4 步 · 生成 + 验收

```bash
cp starter/build_assets.py starter/build_data.py workspace/
# 按数据形态改完后
cd workspace && python3 build_assets.py && python3 build_data.py
python3 ../build_html.py out/我的健康档案.html --data data.json --assets assets.json
python3 ../tools/verify.py data.json assets.json out/我的健康档案.html
```

`verify.py` 过了**还不算完**，必须**在浏览器里真的点一遍**，
清单在 `docs/30-build-verify.md`。

---

## 第 5 步 · 交付 + 告诉他怎么维护

把产物交给他时说清三件事：

1. **这是一个文件，双击就能开**，不联网、不上传，可以自己备份或存网盘。
   **也建议下次看医生时带上**——存手机里、或发到自己邮箱，诊室里没信号也能打开。
   医生最想看的趋势在「化验趋势」，要核对原件就在「报告库」里点开 PDF。
2. **下次有新报告**：把新文件丢进 `workspace/inbox/`，再跟我说一声「更新档案」即可。
3. **这不是诊断**。页面只是把他已有的报告重新组织展示，
   任何数值和结论都以医生解读为准；页脚的免责声明请保留。

最后问一句他想不想调整（比如某个指标想放到概览、某类报告想单独分组），
这些都在数据层改，不用动模板。
