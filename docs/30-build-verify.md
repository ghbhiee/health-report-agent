# 生成与验收

---

## 1. 生成

```bash
cp starter/build_assets.py starter/build_data.py workspace/
cd workspace
python3 build_assets.py                       # → assets.json
python3 build_data.py                         # → data.json
cd .. && python3 build_html.py workspace/out/我的健康档案.html \
        --data workspace/data.json --assets workspace/assets.json
```

`build_html.py` 只做三处字符串替换（`/*__DATA__*/null` 等），**永远不用改它**。
产物是模板逐字节 + 内嵌数据，所以零联网、双击即开。

**产物放 `workspace/out/`**，那里已被 gitignore。**不要 commit、不要外发。**

---

## 2. 脚本校验

```bash
python3 tools/verify.py workspace/data.json workspace/assets.json \
        workspace/out/我的健康档案.html
```

四项：契约合规 / 引用完整 / 交叉校验 / 零外链。细节见
[`20-extract.md` §4](20-extract.md)。

**交叉校验报出不一致时不要改数**——列给用户核对原件。

## 3. 浏览器验收清单

**脚本过了不算完。** 下面每一条都是在真实数据上踩出来的，逐条点一遍。

```bash
python3 -m http.server 8000 --directory workspace/out
# 打开 http://localhost:8000/我的健康档案.html
```

### 基本
- [ ] Console **零报错**。
- [ ] 5 个视图都能渲染：概览 / 化验趋势 / 报告库 / 影像图库 / 对比分析。
- [ ] 顶部身份栏、页脚免责声明都在。**免责声明不能删。**
- [ ] 深色浅色各看一遍。
- [ ] **双击本地文件（`file://`）也能打开**——模板已避开所有联网 API，
      `localStorage` 有 try 兜底。

### 报告抽屉
- [ ] 报告库里每一份都能点开抽屉。
- [ ] **抽屉能滚到底**。踩过的坑：`#drawer-content` 必须是撑满高度的 flex 列，
      `.dbody` 要 `min-height:0` 才滚得动。
- [ ] 抽屉里的图和 PDF 页面渲染图都显示出来了。
- [ ] **抽屉里的图不能用 `loading="lazy"`**——在不滚动的容器里它们永远不加载。
- [ ] 「下载 PDF」「打开原件」能用；合并会话的报告要能逐份下载各自的原件。

### 弹窗 + 抽屉 = 左右分屏（最容易坏的一处）
- [ ] 概览「需要关注的指标」→ 点开某个指标的弹窗 → 点弹窗里的「来源报告」：
      **弹窗收窄到画面左半部分**（不遮挡、不变透明、仍可点），抽屉在右半部分。
- [ ] 此时**连续点弹窗里不同日期的「来源报告」，右边抽屉要跟着换**——这是分屏的意义。
- [ ] 关掉抽屉后，弹窗恢复居中原大小。
- [ ] 反向也要成立：抽屉里点化验行开弹窗，同样分屏。
- [ ] 窄屏（<1000px）放不下两栏时，自动退回居中弹窗 + 抽屉盖在上面。

> 原始 z-index 抽屉 90 < 弹窗 100，会让抽屉藏在弹窗背后点不到。模板用
> `--drawer-w` + `.modal.split` / `.scrim.split` / `.drawer.front` 解决：
> 弹窗宽度 = `calc(100vw - var(--drawer-w) - 30px)`，且遮罩在分屏时必须
> `pointer-events:none`，否则会挡住弹窗点不动。改模板时别把这几条弄丢。

### 来源报告里高亮「当前指标」
- [ ] 从某指标的趋势弹窗点「来源报告」，右侧抽屉的化验明细表里那一行要有标记
      （左侧竖条 + 浅底 + 加粗 + 「当前指标」小标签），**并自动滚动到可见位置**
      （一份报告常有 20–35 行）。
- [ ] 从报告库或时间轴**直接**打开报告时，**不应**有任何高亮。

> 标记刻意不用红/蓝——那两色在结果列已经表示偏高/偏低。标记靠结构 + 文字标签，
> 不靠颜色单打，色觉障碍用户也能分辨。

### 图库与键盘
- [ ] 随便点几张图，灯箱能打开、能左右翻页、能缩放。
- [ ] **Esc 只关最上面那一层**（灯箱 → 抽屉 → 弹窗），不要一次全关。

### 数据本身
- [ ] 趋势图的参考区间带对得上；参考区间变过的项目，带子应该是**分段**的。
- [ ] 对比分析选两次批次，能列出变化最大的项，数字对得上。
- [ ] 抽几个异常值回原始报告核对一遍——**这一步别省**。

## 4. 预览面板的两个陷阱

如果你用的是 IDE 内置预览或无头浏览器：

- **截图对已滚动 / 深色内容有时合成不准**。以 `getComputedStyle` / `naturalWidth` /
  DOM 计数为准，别只信截图。
- 预览面板常处于 `visibilityState: 'hidden'`，此时 **CSS 过渡不会推进**
  （抽屉会停在 `translateX(100%)`，命中测试和截图都不准），
  **`img.decode()` 也永远不会 resolve**（别 await 它，会挂住）。
  验证层级前先注入 `*{transition:none!important}` 再量，别把这个误判成 bug。

## 5. 交付

跟用户说清楚三件事：

1. **这个文件是自包含的**——拷到任何地方、断网都能打开，不联网不上传。
2. **数据可信到什么程度**——哪些核对过、哪些没有、哪些读不清标了待核对。
   （这些也应该写在 `footNotes` 里）
3. **它不是诊断**。页面只是把已有报告重新组织展示，解读以医生意见为准。

如果文件太大（内嵌 PDF 会让 20–50 份报告到 10–35MB），可以在 `build_assets.py` 里
把 `EMBED_PDF` 设成 `False`：不内嵌 PDF 原件、只留页面渲染图，体积降到约 1/5，
代价是抽屉里不能下载原件。
