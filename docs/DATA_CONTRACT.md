# 数据契约（DATA CONTRACT）

模板 `template/app_template.html` 是一个**黑盒前端**：你只要产出下面三个 JSON，
`build_html.py` 把它们塞进模板，就得到一个可双击打开的自包含 HTML。
不同来源的数据千差万别，但**只要最终产出符合本契约，页面功能就完全一致**。

`demo/make_demo.py` 是这份契约的**可运行范例**——下面每个字段它都至少填了一次，
改数据前先跑一遍它、打开产物看看，比读文档快。
写完自己的 JSON 后跑 `python3 tools/verify.py` 校验是否合规。

三个占位符（模板里各出现一次，勿改名）：
`/*__DATA__*/null`、`/*__ASSETS__*/null`、`/*__MANIFEST__*/null`
分别被替换成 `data.json`、`assets.json.assets`、`assets.json.manifest`。

---

## 1. `data.json`

```jsonc
{
  "patient":  { … },        // 顶部身份栏
  "reports":  [ … ],        // 每份报告一条（超声可多项合并，见下）
  "panels":   [ … ],        // 化验，按分类分面板，每项是一条时间序列
  "grades":   [ … ],        // 可选：BI-RADS/TI-RADS 分级随访
  "clusters": [ … ],        // 可选：体检批次（对比分析用；缺省则对比页为空）
  "threads":  [ … ],        // 可选：健康主线
  "banner":   { … },        // 可选：页面顶部通栏提示（缺省不显示）
  "galleryNote": "…",       // 可选：图库顶部说明（缺省用通用句）
  "footNotes": [ … ]        // 可选：页脚的「数据来源/核对」等说明
}
```

### patient
```jsonc
{ "name": "张三", "sex": "女", "age": 48, "hospital": "…医院" }
```
`sex / age / hospital` 均可省略。

### reports[]  — 一条 = 一份报告（或一次合并的多项检查）
```jsonc
{
  "no": "01",                    // 唯一 id，也是 ASSETS['pdf01'] / MANIFEST 的键
  "seq": 1,                      // 排序用序号（可选）
  "date": "2026-01-22",          // YYYY-MM-DD
  "name": "血常规（五分类）",
  "type": "检验报告",             // 检验报告 / 超声报告 / 放射报告 / 心电报告 / …
                                 //   时间轴按 type 分行；决定报告库筛选项
  "conclusion": "…",             // 诊断结论 / 主要结果（可含换行）
  "findings": "…",               // 可选：检查所见（影像类）
  "status": "异常",              // 异常 / 正常 / 见结论 —— 决定徽标颜色与时间轴圆点色
                                 //   约定：检验报告有偏离项=异常，否则正常；
                                 //   影像类"未见明显异常"=正常，其余=见结论
  "file": "01_血常规.pdf",       // 原始文件名（下载 PDF 用）

  // ↓ 以下都可省略；省略时模板按「单 PDF、无图、未合并」兜底
  "sources": [                   // 这条报告对应的原件 PDF，可多份（合并会话）
    { "no": "01", "file": "01_….pdf", "name": "血常规" }
  ],
  "exams": ["血常规"],           // 合并会话里包含的各项检查名
  "merged": 1,                   // 合并了几项（>1 时抽屉显示"本次共 N 项检查"）
  "tw": ["tw00"],                // 关联的「图文报告」文档 id（MANIFEST 里 kind:'tw'）
  "imgs": [                      // 直接挂在这份报告上的诊断图（内镜/超声帧等）
    { "k": "md01_0", "cap": "结肠镜图 1" }
  ],
  "abnItems": [                  // 本次偏离项（抽屉里用徽标列出；一般由 panels 汇出）
    { "name": "隐血", "t": "+++", "f": "A", "ref": "阴性", "unit": "" }
  ]
}
```

> **图片可以挂两处，二选一或都用**，取决于医院怎么发报告：
> - `report.imgs[]` —— 图**就在这份报告的 PDF 里**。一份报告一份 PDF、图印在上面时走这条
>   （常见于内镜报告、单项超声）。
> - `report.tw[] → MANIFEST(kind:'tw').imgs[]` —— 图在**一份独立的「图文报告」PDF** 里，
>   而那份图文往往**覆盖同一次的好几项检查**（常见于一次做了甲状腺+颈动脉+腹部的彩超：
>   报告单一项一份，留图却只有一份图文）。这时图挂在图文文档上，几份报告共同引用它。
> 图库和报告库会自动从两处收集，无需你区分。

### panels[]  — 化验，每个面板一类
```jsonc
{
  "key": "cbc",                  // 唯一短 id
  "label": "血常规",
  "dates": ["2024-01-26","2025-03-14","2026-01-23"],   // 该面板出现过的日期（升序）
  "groups": ["白细胞系","红细胞系","血小板系","其他"],  // 可选：项目分组小标题；null=不分组
  "numericCount": 20,            // 数值型项目数（=0 时该面板按"定性"呈现，不画趋势）
  "items": [ … ]
}
```
`items[]`：
```jsonc
{
  "name": "白细胞计数", "unit": "10E9/L",
  "ref": "4.0-10.0",             // 展示用参考区间文本
  "refVaries": false,            // true=不同日期参考区间不一致（表格加 * 注释）
  "lo": 4.0, "hi": 10.0,         // 最近一次的数值区间（画参考带用；开区间可为 null）
  "numeric": true,               // 是否画趋势图/量程条（false=纯定性，只进表格）
  "abn": true,                   // 是否曾经偏离（进"需要关注"）
  "abnLatest": false,            // 最近一次是否仍偏离
  "group": "白细胞系",           // 可选，配合 panel.groups
  "vals": [                      // 每次测量一条，按日期升序
    { "d":"2024-01-26", "v":5.24, "f":null, "t":"5.24",
      "ref":"4.0-10.0", "lo":4.0, "hi":10.0, "src":"26" }
    //  v = 数值(null 表示纯定性)   t = 原样显示文本(如"5.24"/"阴性"/"+++(200)"/"Ⅲ")
    //  f = 偏离标记：'H' 高 / 'L' 低 / 'A' 定性异常 / null 正常
    //  lo/hi/ref = 这一次自己的参考区间（关键！随报告可变，见"坑"）
    //  src = 来源报告 no（点数值可跳到该份报告）
  ]
}
```

### grades[]  — 可选，结节分级随访（直接摘自结论，不要推断）
```jsonc
{ "date":"2026-01-22", "sys":"TI-RADS", "grade":"4b",
  "what":"左侧甲状腺结节",       // 部位（按同 sys+what 归为一条随访线）
  "name":"甲状腺超声", "report":"08" }   // report=点某一步要打开的报告 no
```

### clusters[]  — 可选，体检批次（对比分析用）
```jsonc
{ "id":"2026-01-22", "label":"2026年01月",
  "dates":["2026-01-22","2026-01-23","2026-02-02"],   // 归为同一次的所有化验日期
  "span":"2026-01-22 ~ 2026-02-02" }
```
一次体检常分散在几天。缺省时对比页显示"没有可对比的化验"。

### threads[]  — 可选，健康主线
```jsonc
{ "title":"甲状腺结节随访", "icon":"🦋", "note":"……一句话叙述……",
  "reports":["08","07"] }        // 相关报告 no（点 chip 打开）
```

### banner  — 可选，页面顶部通栏提示
```jsonc
{ "title":"演示数据", "text":"本页所有姓名、日期、化验值与图片均为虚构。" }
```
也可以直接给一个字符串（等价于只有 `text`）。缺省时整条通栏不渲染。
用于「这份档案有什么必须一眼看到的前提」——`demo/` 用它声明全部数据为合成。
一般的个人档案不需要它。

### footNotes[]  — 可选，页脚说明（隐私声明与免责声明模板会自动追加）
```jsonc
[ { "label":"数据来源", "text":"…" }, { "label":"数据核对", "text":"…" } ]
```

## 2. `assets.json.assets`  — `{ 键: dataURI }`

所有二进制都内联成 data URI，页面因此零外链、零 fetch。键名约定：

| 键 | 内容 | 生成 |
|---|---|---|
| `pdf<no>` | 原始 PDF 的 **base64（不带 data: 前缀）** | `base64(pdf_bytes)` |
| `pg<no>_<n>` | 第 n 页的整页渲染图，WebP data URI | PyMuPDF 渲染→WebP |
| `md<no>_<i>` / `md<tw>_<i>` | 提取出的诊断图，WebP data URI | 抽图/裁切→WebP |

> `pdf*` 存**裸 base64**（模板里 `atob` 后转 Blob 供下载/新标签页打开）；
> `pg*`/`md*` 存**完整 data URI**（直接进 `<img src>`）。别搞混。

## 3. `assets.json.manifest`  — `[ 每个文档一条 ]`
```jsonc
{
  "kind": "report",              // 'report'=报告原件 / 'tw'=图文报告文档
  "no": "01",                    // = reports[].no（report）或 tw id（tw）
  "file": "01_血常规.pdf",
  "pages": ["pg01_0"],           // 整页渲染图的键，按页序
  "imgs": [                      // 该文档里的诊断图（tw 文档的图放这；report 一般为空）
    { "k":"mdtw00_0", "cap":"甲状腺超声 · 第 1/2 张" }
  ],
  "exams": ["甲状腺超声","肝胆胰脾超声"],  // 可选(tw)：该图文覆盖的检查
  "aliases": ["甲状腺_图文1.pdf","腹部_图文1.pdf"]  // 可选(tw)：被复制的多个原文件名
}
```

## 必填 vs 可选（最小可用集）

**最小**只需要：`patient.name`、`reports[]`（每条至少 no/date/name/type/conclusion/status/file）、
`panels[]`（可为空数组 `[]`）。其余全部可省，模板会隐藏对应板块或按兜底渲染：

- 无 `panels` → 化验趋势/对比页为空提示
- 无 `grades` → 不显示"结节分级随访"
- 无 `threads` → 不显示"健康主线"
- 无 `clusters` → 对比页提示无可对比
- 无 `sources` → 用 `[{no,file,name}]` 兜底
- 无 `imgs`/`tw` → 该报告无图，图库跳过

一条报告要能"下载 PDF / 打开原件页面"，它的每个 `sources[].no` 必须在
`ASSETS['pdf<no>']` 和 `MANIFEST` 里都有对应项。
