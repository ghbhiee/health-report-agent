# 勘探、抽取、核对

数据到手之后、写 build 脚本之前的全部工作。**先勘探，别急着写解析**——
这一节的 9 个坑几乎每份真实数据都会中招几条，先看一遍能省下大量返工。

---

## 1. 勘探

```bash
python3 tools/probe.py workspace/inbox
```

它逐个文件回答一个问题：**这份东西该怎么读**。输出会把文件分成两拨：

- **第 1 层**：PDF 有文字层、或 Excel 表格 → 机器直接取，零误差
- **第 2 层**：扫描件、照片、长截图、视频帧 → **你自己看图读**

判据是每页的字符数。低于 120 字/页基本就是扫描件——数字版报告一页动辄几百字。

勘探时顺便回答这几个问题，它们决定你怎么写 build 脚本：

- 一共几次体检？跨多少年？（趋势图有 2 个点和 5 个点是两种东西）
- 化验数据是**长表**（一行一次测量）还是**宽表**（一行一项、各列是日期）？
- 影像 PDF 里到底有没有图？（`probe.py` 会数「够大可能是诊断图的」有几张）
- 有没有同一次检查的多份重复文件？

## 2. 三层抽取

### 第 1 层：PDF 有文字层 → 直接取

```bash
python3 tools/extract.py text workspace/inbox/报告.pdf
python3 tools/extract.py text workspace/inbox/报告.pdf --json    # 给脚本用
```

确定、免费、零误差、跨平台。真实数据里 CT / MR / 超声 / 内镜报告大多属于这类，占大头。

注意 `get_text()` 出来的表格是按阅读顺序展平的，列关系要你自己按行重建。
实在乱就用 `page.get_text('words')` 拿带坐标的词，按 x 切列、按 y 聚行。

### 第 2 层：没有文字层 → **你自己读图**

```bash
python3 tools/extract.py pages workspace/inbox/扫描件.pdf     # → workspace/raw/pages/*.png
```

然后**用 `Read` 逐张打开这些 PNG，把数值读出来**。

这一层是这个项目和老式工具包最大的区别：**不需要装任何 OCR 引擎**。
跑这个仓库的 agent 本身就是多模态模型，读中文化验单比 OCR 准得多——OCR 会把
罗马数字 Ⅲ 认成 III 或 11，会把 `≥` 认成 `2`，你不会。

**读数三条规矩（重要）：**

1. **异常值复读一次**再定稿。偏高偏低那几项是用户最在意的，读错代价最大。
2. **读不清就标「待核对」**并告诉用户，**绝不猜一个像样的数字填进去**。
   宁可页面上少一项，也不能多一项错的。
3. **参考区间照抄原文**：`12.3-107.0`、`≥50`、`阴性`、`I-II` 原样存，
   不要归一化、不要换算、不要「顺手」统一格式。

### 第 3 层：量大到撑爆上下文 → 可选的子进程分批

只有几十份报告、上百页时才需要：

```bash
python3 tools/fanout.py --check                      # 看有没有可用的 CLI
python3 tools/fanout.py workspace/raw/pages/*.png --out workspace/raw/extracted.json
```

它探测 `claude` / `codex` 谁在就用谁。**都没有也没关系**——它会直接告诉你，
你自己分批用 `Read` 读就是了。**任何 CLI 都不是这个项目的依赖**，别把它写成前提。

子进程读回来的东西**要抽查**。`fanout.py` 会把子进程标为「读不清」的项目列出来，
那些必须你自己看原图确认。

## 3. 九个反复出现的坑

这些是在真实数据上一个一个踩出来的。勘探时逐条对照。

### §4.1 压缩包中文文件名乱码
Windows 打的包在 macOS/Linux 上解出来是乱码。用 `lib.unzip_cjk()`
（按 cp437 → utf-8/gbk/big5 试探修回）。

### §4.2 同一次检查的多项，共用一份「合并报告」
超声尤其常见：一次做了甲状腺+乳腺+腹部，医院出**一份**报告，
导出却把**同一段结论复制到每一项**上，PDF 也各存一份，只有页眉不同。

→ 按 `(日期, 所见+结论的 hash)` 把它们**合并成一条**报告，
`sources[]` 里放各自的 PDF，`exams[]` 放各项检查名，`merged` = 项数。
**判据是内容，不是文件名。**

demo 里的报告 16 就是这个形态，可以打开看效果。

### §4.3 参考区间会随时间 / 随报告变 ⭐
实验室会改判读标准。真实案例：某项 25-羟维生素D，2024 年的报告印
`12.3-107.0`，2026 年改成 `≥50 正常`。汇总表把两者**压成了一个区间**，
结果一个正常值被标成了偏高。

→ **参考区间必须逐次存**（`vals[].lo/hi/ref`），不能只存项目级。
模板会按每次自己的区间分段画参考带，`refVaries: true` 会让表格加 `*` 注释。

这是整个契约里最容易做错、后果最严重的一条。demo 的「专项检查 → 25-羟基维生素D」
就是照这个案例造的，打开那个指标的弹窗能看到三次的区间不一样。

### §4.4 影像 PDF 里常常没有影像图
CT / MR / 钼靶 / DR 的报告 PDF 往往**只有文字**，内嵌的图只是院徽、二维码、医生签名。
心电图的波形是**矢量图**（提取不出位图，但整页渲染看得到）。

→ 按尺寸过滤，`extract.py images` 默认丢掉最大边 ≤160px 的。
一张都提不到很正常，**在 `DATA.galleryNote` 里如实说明**哪些报告没有可提取的图、
让用户去报告库看原件页——别假装有。

### §4.5 网格拼图要按坐标裁
内镜报告常把 8 张图拼在一整页扫描图里，`get_images()` 只会给你一张大图。
→ 固定行列坐标裁切（PIL 的 `im.crop((l, t, r, b))`）。

### §4.6 「图文报告」被复制成多份、文件名里的日期还是错的
真实案例：47 个图文文件其实只有 18 份不同文档（同一份按每个检查名各存一次），
而且**文件名里的日期会串**（把 A 日期的文件挂到 B 日期名下）。

→ 按**内容 hash 去重**（`lib.dedup_pdfs`），再按 **PDF 正文里印的检查日期**归位。
**别信文件名。** 被合并掉的文件名记进 manifest 的 `aliases`，
用户还能按自己知道的名字找到它。

### §4.7 化验是长表 vs 宽表
- **长表**：一行一次测量（报告日期 / 项目 / 结果 / 单位 / 参考区间）
- **宽表**：一行一项，各列是日期

→ 长表要自己 pivot 成「每项一条时间序列」。`starter/build_data.py` 的
`to_panels()` 就是干这个的，直接拿去改。

### §4.8 一次体检分散在好几天
抽血周一、超声周五，日期不同其实是同一次体检。
→ 用 `lib.cluster_dates()` 聚成「体检批次」写进 `clusters`，
否则「对比分析」会默认拿两个不相干的日期比，结果 0 项。

### §4.9 定性异常汇总表常漏标
汇总表往往只认 ↑↓ 箭头，不认罗马数字和定性项（清洁度 Ⅲ、隐血 +++）。
→ 用 `lib.qual_flag()` 按**各报告自己印的参考标准**补判，
并在 `footNotes` 里说明你补了哪些。

## 4. 核对：让这份档案值得信任

原来的私人工具包靠 OCR 把化验单回读一遍、和汇总表逐格对撞，
**靠这一步发现过真实的数据缺陷**（就是 §4.3 那个）。
现在没有第二份数据源来对撞了，用三件事补上：

### ① 结构上杜绝
参考区间逐次存（§4.3）。这类 bug 从数据结构上就不可能发生了。

### ② 交叉校验：你算的 vs 报告印的

```bash
python3 tools/verify.py workspace/data.json workspace/assets.json workspace/out/xxx.html
```

它拿每次测量**自己的** `lo/hi` 重算一遍偏离标记，和你存进 `f` 的对比。
如果你的 `f` 填的是**报告上印的 ↑↓**，这就是在拿「实验室的判断」和
「实验室自己印的区间」对撞——对不上说明其中一边有问题。

> **不一致时不要改数。** 列出来给用户，让他对着原件核对。
> 你的角色是发现矛盾，不是消除矛盾。

### ③ 有第二份数据就一定要对撞
如果数据里恰好既有汇总表、又有逐份报告，**两边都抽然后比对**。
那才是真正的双源核对，比什么自检都强。

### 把核对结论写进页面
```jsonc
"footNotes": [
  {"label":"数据核对","text":"逐份 PDF 与汇总表对撞，182 项中 179 项一致；
   3 项不一致已列在下方，建议核对原件。另有 2 项因扫描件模糊未能读取。"}
]
```
用户看到这句才知道**这份档案能信到什么程度**。写实话，包括没做到的部分。
